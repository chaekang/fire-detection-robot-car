# 화재 탐지 기반 장애물 회피 로봇카

4개의 IR 센서로 검은 선을 따라 주행하고, 초음파 센서로 전방 장애물을 확인하는 라즈베리파이 기반 팀 프로젝트입니다. 장애물을 만나면 카메라 영상을 별도 PC 서버로 보내 화재 여부를 판정받습니다. 일반 장애물은 회피하고, 화재로 판정된 대상 앞에서는 정지한 채 감지 결과를 계속 확인합니다.

2025년 2학기 센서프로그래밍 수업에서 3인 팀으로 제작했습니다. 실제 시연에서는 **불 이미지가 있는 대상 앞에서 정지하는 단계까지 확인**했습니다. 펌프 구동 회로를 완성하지 못했으므로 **물 분사와 실제 화재 진압은 수행하지 않았습니다.** 코드의 일부 함수명과 출력문에 있는 ‘화재 진압’은 실제 소화 성능을 뜻하지 않습니다.

## 구현한 기능

- IR 센서 4개의 입력 조합에 따른 라인트래킹과 선을 놓쳤을 때 좌우 재탐색
- 초음파 센서의 거리 측정, 전방 장애물 감지와 정지
- 좌우 IR 센서와 MPU6050의 yaw 추정값을 활용한 장애물 회피 및 라인 복귀
- I2C 명령을 통한 DC 모터와 카메라 서보 제어
- 카메라 프레임의 TCP 전송과 PC 서버의 화재 판정 수신
- OLED 표정, LED 점멸, 버저를 통한 상태 표시

## 시스템 구성

```text
IR / 초음파 / MPU6050 → Raspberry Pi → 모터 / 서보 / OLED / LED / 버저
                              ↕ TCP
                         PC 화재 판정 서버
```

이 저장소에는 **라즈베리파이 제어 소스만 포함**되어 있습니다. PC의 YOLO 서버 소스, `best.pt` 모델, 학습 데이터와 보드 펌웨어는 포함되어 있지 않습니다. 따라서 저장소를 내려받는 것만으로 화재 탐지 시스템 전체를 실행할 수는 없습니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `main.py` | 초기화, 장애물 처리, 라인트래킹과 종료 처리 |
| `config.py` | GPIO 핀, I2C 주소와 공통 설정 |
| `sensor_utils.py` | 라인 센서, 초음파 거리와 IR 장애물 센서 읽기 |
| `line_tracking.py` | 라인트래킹, 방향 보정과 라인 재탐색 |
| `ir_obstacle_detection.py` | 장애물 판정, 회피, 복귀와 화재 미감지 대기 |
| `motor_control.py` | STM8 보드에 모터와 서보 명령 전송 |
| `camera_control.py` | 카메라 서보 제어 |
| `imu_sensor.py` | MPU6050 초기화, 자이로 보정과 yaw 추정 |
| `fire_detection.py` | Picamera2 촬영, JPEG 전송과 서버 응답 수신 |
| `display_control.py` | SSD1306 OLED 상태 표시 |
| `led_control.py` | LED 점멸 제어 |
| `buzzer_control.py` | 버저 초기화와 상태별 음향 |
| `avoid_check.py` | 최종 메인 루프와 별도로 사용하는 단순 회피 스크립트 |

`code.zip`과 `__pycache__`는 중복 자료와 실행 캐시이므로 제외했습니다. 원본 폴더의 Python 소스 13개를 모두 포함했으며, 공개 준비 과정에서 줄 끝 공백과 줄바꿈 형식만 정리했습니다.

## 하드웨어와 설정

Raspberry Pi, 카메라, STM8 제어 보드, DC 모터, 카메라 서보, MPU6050, SSD1306 OLED, IR 센서, 초음파 센서, LED와 버저가 필요합니다. 카메라의 정확한 모델은 기록되어 있지 않습니다.

GPIO 번호는 `GPIO.BOARD` 기준의 **물리 핀 번호**입니다. 실제 배선과 반드시 대조하세요.

| 장치 | 코드의 설정값 |
|---|---|
| 라인 센서 L1 / L2 / R1 / R2 | 13 / 15 / 11 / 7 |
| 초음파 TRIG / ECHO | 16 / 18 |
| 좌우 IR / IR 스위치 | 21 / 19 / 22 |
| 상태 LED | 12 |
| 버저 | 32 (`buzzer_control.py`) |
| I2C 버스 | 1 |
| STM8 / MPU6050 / OLED 주소 | `0x16` / `0x68` / `0x3c` |
| 카메라 서보 번호 | 4 |

## 실행 준비

### 1. 라즈베리파이 환경 준비

원본 실행 환경의 OS 및 패키지 버전은 기록되어 있지 않습니다. 아래는 코드에서 확인한 직접 의존성 목록이며, 특정 버전 조합의 재현을 보장하는 설치 명세는 아닙니다.

| import | 필요한 패키지 |
|---|---|
| `RPi.GPIO` | RPi.GPIO |
| `smbus` | python3-smbus 또는 smbus |
| `cv2` | OpenCV |
| `picamera2` | Picamera2 |
| `luma.core` / `luma.oled` | luma.core / luma.oled |
| `PIL` | Pillow |

Raspberry Pi OS에서 카메라와 I2C를 사용할 수 있도록 설정하고, 해당 OS와 보드에서 지원하는 패키지를 설치하세요. `imu_sensor.py`는 import 시 MPU6050을 초기화하고 약 3초간 자이로 보정값을 수집하므로, 실행을 시작할 때 차체를 고정해야 합니다.

### 2. 별도 PC 서버 준비

원 프로젝트에서 사용한 서버 소스와 모델 파일은 현재 저장소에 없습니다. 서버는 다음 통신 규약에 맞아야 합니다.

1. TCP 포트에서 라즈베리파이 연결을 받습니다. 원본 설정 포트는 `8000`입니다.
2. 4바이트 big-endian 길이 헤더 뒤에 오는 데이터를 길이만큼 수신합니다.
3. 데이터는 OpenCV로 JPEG 인코딩한 배열을 Python `pickle`로 직렬화한 것입니다.
4. 프레임을 판정하고 화재 감지 시 문자열 `1`을, 미감지 시에는 예를 들어 `0`을 반환합니다. 현재 클라이언트는 수신 문자열이 정확히 `1`인 경우만 화재로 처리합니다.

`pickle` 데이터는 신뢰할 수 있는 라즈베리파이에서만 받아 처리하고, 서버를 신뢰하는 로컬 네트워크 안에서 사용하세요.

**실제 연결 주소는 `fire_detection.py`의 `FireDetector.__init__()`에 직접 들어 있습니다.** 원본에는 `192.168.1.8:8000`으로 설정되어 있으므로 PC 주소에 맞게 바꾸세요. `config.py`의 같은 이름 설정만 바꿔도 클라이언트에 반영되는 구조는 아닙니다.

### 3. 프로그램 실행

장치 연결과 PC 서버를 준비한 라즈베리파이에서 실행합니다.

```bash
git clone https://github.com/chaekang/fire-detection-robot-car.git
cd fire-detection-robot-car
python3 main.py
```

## 현재 구현의 한계

이 저장소는 수업 프로젝트의 소스 기록입니다. 공개 준비 과정에서 주행 로직을 변경하거나 실물 테스트를 새로 수행하지 않았습니다.

- 물 분사와 소화 코드가 없으며, 실제 불꽃을 대상으로 성능을 검증한 기록도 없습니다.
- 라인 교차점 로그에는 ‘90도’라고 나오지만 실제 호출 목표는 `45` 또는 `-45`입니다. 이를 90도 회전 성능으로 해석하지 않습니다.
- 카메라 스캔 함수는 있으나 `main.py`에서 주기적으로 실행하지 않습니다.
- 서버 연결 실패 시 `connect()` 예외가 발생하며, 자동 재연결은 구현되어 있지 않습니다.
- 화재 미감지 대기, 회피 중 라인 찾기와 일부 소켓 수신에는 시간 상한이 없습니다.
- `read_ir_sensors()`는 장애물 감지 시 `True`를 반환하지만 회피 방향 함수의 변수명과 설명이 이를 ‘clear’라고 표현합니다. 실제 회피 방향은 배선과 실물 동작을 다시 확인해야 합니다.
